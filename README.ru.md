Это проект по автоматической тематической классификации русскоязычных постов из
Telegram. Его практическая идея — помочь пользователю справиться с
информационным шумом и видеть в ленте публикации только на интересующие темы.

Материалы охватывают весь путь ML-проекта: сбор и разметку сообщений, анализ и
очистку данных, сравнение подходов к классификации и дообучение RuBERT.

## 🎯 Цель проекта

Построить модель, которая определяет тематическую категорию Telegram-поста по
его тексту. В дальнейшем такой классификатор может стать основой персонального
фильтра новостей.

Модель различает политику, личные публикации, IT, бизнес, Москву, науку,
финансы, разное, игры, рекламу и погоду. В исходном датасете есть ещё класс
`other`, и обучение идёт по всем двенадцати меткам — вместо этого бот не
пересылает `personal` и `other`, отсекая их через `exclude_categories`.

## 📊 Датасет

В `all_channel_posts.csv` находится 22 099 постов из 24 Telegram-каналов,
опубликованных с августа 2023 по декабрь 2024 года.

| Колонка | Содержание |
| --- | --- |
| `message_id` | Идентификатор сообщения Telegram |
| `sender_id` | Идентификатор источника |
| `text` | Исходный текст публикации |
| `date` | Дата и время публикации |
| `channel` | Название канала |
| `category` | Тематическая метка |

Пропусков в данных нет. Во время EDA найдено 772 дубликата текста и заметный
дисбаланс классов: в крупнейшей категории «политика» 4 631 пост, а в категории
«погода» — 406. Поэтому для разбиения используется стратификация, а качество
лучше оценивать не только по accuracy.

## 🧹 Подготовка текста

Пайплайн предобработки:

- приводит текст к нижнему регистру;
- удаляет ссылки, хештеги, упоминания, HTML/Markdown и специальные символы;
- лемматизирует русские слова с помощью spaCy;
- убирает стоп-слова и повторяющиеся подписи Telegram-каналов;
- удаляет дубликаты и публикации с меткой `other`.

В EDA также исследуются длина постов, частые слова и n-граммы, время публикации,
баланс категорий, TF-IDF-признаки, эмбеддинги предложений и проекции t-SNE и
UMAP.

## 📈 Результаты

Классификатор — `DeepPavlov/rubert-base-cased`, дообученный на 12 классах:
5 эпох, батч 8, learning rate 5e-5, последовательности обрезаны до 128 токенов,
чекпоинт выбран по 5-фолдовой стратифицированной кросс-валидации.

На отложенной тестовой выборке из 2 210 постов:

| Метрика | Значение |
| --- | --- |
| Accuracy | 0.781 |
| Macro F1 | 0.77 |
| Weighted F1 | 0.78 |
| Macro ROC-AUC | 0.967 |

Accuracy на кросс-валидации почти не расходится по фолдам — 0.7788, 0.7725,
0.7753, 0.7758, 0.7843, в среднем 0.777, — так что тестовая цифра не следствие
удачного разбиения.

По категориям, по убыванию F1:

| Категория | Precision | Recall | F1 | Поддержка |
| --- | --- | --- | --- | --- |
| `political` | 0.92 | 0.92 | **0.92** | 463 |
| `science` | 0.88 | 0.89 | **0.88** | 128 |
| `it` | 0.83 | 0.86 | **0.84** | 241 |
| `weather` | 0.84 | 0.78 | **0.81** | 40 |
| `gaming` | 0.76 | 0.81 | **0.79** | 52 |
| `moscow` | 0.75 | 0.84 | **0.79** | 192 |
| `finances` | 0.81 | 0.76 | **0.78** | 114 |
| `personal` | 0.77 | 0.70 | **0.73** | 339 |
| `advertisement` | 0.80 | 0.64 | **0.71** | 44 |
| `business` | 0.74 | 0.67 | **0.70** | 203 |
| `stuff` | 0.61 | 0.69 | **0.65** | 61 |
| `other` | 0.61 | 0.66 | **0.63** | 333 |

Интересен как раз разброс. У `political` и `science` есть собственная лексика, и
они уходят выше 0.88, а два класса-свалки — `other` и `stuff` — оказываются в
самом низу, и это ровно то, чем класс-свалка и является: своей лексики у него
нет, есть только отсутствие чужой. У `advertisement` самый резкий разрыв между
precision и recall (0.80 против 0.64), то есть примерно треть рекламы всё ещё
проходит под другой меткой.

### Почему трансформер

Первый же вопрос — сколько даёт дешёвая линейная модель на тех же данных,
поэтому в EDA посчитаны две, ровно на этом разбиении: тот же
`train_test_split`, те же пять стратифицированных фолдов, те же 12 классов, та
же очистка текста:

| Модель | CV accuracy | Test accuracy | Test macro F1 |
| --- | --- | --- | --- |
| TF-IDF + LogisticRegression | 0.733 ± 0.006 | 0.736 | 0.714 |
| TF-IDF + LinearSVC | 0.733 ± 0.004 | 0.734 | 0.707 |
| **RuBERT, дообученный** | **0.777** | **0.781** | **0.77** |

Дообучение даёт примерно 4.5 пункта accuracy и 5.6 пункта macro F1 поверх
логистической регрессии. Основная часть выигрыша — на классах, где ключевых слов
не хватает: `other` растёт с 0.55 до 0.63 по F1, `business` — с 0.62 до 0.70.
А на самом простом классе разница почти нулевая: `political` идёт с 0.89 до
0.92, потому что его лексику ни с чем не спутать. Две линейные модели при этом
неотличимы друг от друга — обычный исход, когда признаки TF-IDF уже
зафиксированы.

Базовые модели не тюнились и работают без лемматизации, так что 4.5 пункта
стоит читать как верхнюю оценку пользы от трансформера: достаточно, чтобы
оправдать `torch` в деплое, но недостаточно, чтобы считать линейную модель
безнадёжной.

Все числа взяты из [`notebooks/model.ipynb`](notebooks/model.ipynb) и
[`notebooks/eda.ipynb`](notebooks/eda.ipynb) и приведены так, как их показывают
сохранённые выводы ячеек.

## 🚀 Запуск

Установите зависимости, скачайте пайплайн spaCy и поставьте git-хуки:

```sh
task init
```

Распакуйте модель классификатора в `model/` рядом с `pyproject.toml`:

```sh
curl -L -o model.zip "https://files.nktkln.com/Projects/Telegram%20News%20Classifier/model/model.zip" && unzip -j model.zip -d model && rm model.zip
```

Скопируйте шаблон настроек и впишите свои API ID и hash:

```sh
cp .env.example .env
```

Войдите один раз. Telethon спросит номер телефона и код, который пришлёт
Telegram, а затем создаст `news_classifier.session` — его переиспользуют все
последующие запуски:

```sh
task login
```

Запустите бота:

```sh
task run
```

При первом запуске создаётся форум-супергруппа и по одной теме на категорию, а
их идентификаторы записываются в `config/forum_state.yaml`. Удалите этот файл —
и следующий запуск создаст новый форум.

## 🔧 Конфигурация

Учётные данные и пути живут в `.env`, который читает `pydantic-settings`; в
`.env.example` перечислены все переменные вместе со значениями по умолчанию.

| Переменная | По умолчанию | Что это |
| --- | --- | --- |
| `API_ID`, `API_HASH` | — | Учётные данные Telegram; обязательны |
| `SESSION_NAME` | `news_classifier` | Файл сессии Telethon, без расширения |
| `MODEL_PATH` | `model` | Каталог с моделью и её токенизатором |
| `DB_PATH` | `messages.db` | Файл DuckDB с недавно увиденными постами |
| `TAXONOMY_PATH` | `config/categories.yaml` | Названия категорий и списки исключений |
| `FORUM_STATE_PATH` | `config/forum_state.yaml` | Идентификаторы форума и тем; пишет бот |
| `FORUM_TITLE` | `News` | Название форума, создаваемого при первом запуске |
| `MESSAGE_LIFETIME` | `2` | Сколько часов пост остаётся кандидатом в дубликаты |
| `SIMILARITY_THRESHOLD` | `0.1` | Мера Жаккара, выше которой посты считаются одной новостью |
| `SPACY_MODEL` | `ru_core_news_sm` | Пайплайн, которым выполняется лемматизация |
| `DISABLE_LOGGING`, `LOG_LEVEL`, `LOG_PATH` | `false`, `INFO`, пусто | Приёмники Loguru; без `LOG_PATH` логи идут только в stdout |

Таксономия — это структура, а не настройка, поэтому она остаётся в YAML:

```yaml
categories:
  0: "business"
  1: "it"
  # ...
exclude_categories:
  - 9  # advertisement
exclude_channels: []
```

Ключи внутри `categories` — это индексы классов, которые предсказывает модель.
Переименовывайте их свободно: имена становятся лишь заголовками тем. Но никогда
не меняйте нумерацию и не добавляйте новые — двенадцатый индекс модель выдать не
может. `exclude_categories` убирает класс без переобучения и не создаёт для него
тему; `exclude_channels` исключает каналы целиком, по отрицательному
идентификатору чата `-100…`, который Telegram использует для супергрупп и
каналов.

`config/forum_state.yaml` — это состояние, а не конфигурация. Его пишет сам бот,
он в `.gitignore`, и только он не даёт при перезапуске создать второй форум.

> [!IMPORTANT]
> `MESSAGE_LIFETIME` задаёт и то, как долго хранятся посты, и то, как часто они
> удаляются, — то есть определяет, насколько далеко назад видит фильтр
> дубликатов. Увеличение ловит более медленные повторы ценой сравнения с
> бо́льшим числом наборов лемм.

## 🧠 Как обрабатывается пост

Каждое новое сообщение из канала проходит одну и ту же последовательность, и
любой шаг может её прервать:

| Шаг | Пост отбрасывается, если |
| --- | --- |
| Проверка источника | Это не пост канала, в нём нет текста или канал указан в `exclude_channels` |
| Поиск в базе | Его идентификатор или идентификатор его альбома уже сохранён |
| Фильтр дубликатов | Его леммы пересекаются с постом за последние `MESSAGE_LIFETIME` часов сильнее `SIMILARITY_THRESHOLD` |
| Классификатор | Предсказанная категория указана в `exclude_categories` |
| Поиск темы | Для этой категории ещё нет темы |

Всё, что осталось, пересылается в тему своей категории. Альбомы пересылаются
целиком: первое сообщение альбома ждёт секунду своих соседей, чтобы набор
фотографий не превратился в одну.

Фильтр работает по очищенному тексту, а не по исходному. `preprocess_text`
убирает HTML и Markdown, а затем всё, что не является латинской или кириллической
буквой, — ровно в таком виде обучалась модель. Одна и та же функция питает и
проверку дубликатов, и классификатор, поэтому они не могут разойтись в том, что
написано в посте.

требует проверки на самой модели, а не правки файла блокировки.

## 🐳 Docker

```sh
task docker-build
task docker-login   # только при первом запуске, спросит код из Telegram
task docker-run
```

Сборка двухэтапная: builder ставит зависимости из `uv.lock` с
`--frozen --no-dev` в `/opt/venv`, скачивает пайплайн spaCy и распаковывает
модель классификатора в `/opt/model`; финальный этап копирует всё это в чистый
`python:3.13-slim` и запускается от имени `shrimp` — пользователя без root с
фиксированными UID и GID `10000`.

Модель лежит в `/opt/model`, а не в рабочей директории, и это намеренно:
`compose.yml` монтирует `./config` и `./state` внутрь контейнера, а любое
монтирование поверх `/app` скрыло бы модель, уже вшитую в образ. Всё, что пишет
бот, — файл сессии и база сообщений — попадает в `/state`, поэтому сам образ на
практике остаётся доступным только для чтения.

## 📁 Структура исходников

```
src/news_classifier/
  settings/       AppSettings; контракт .env
  domain/         Post, Taxonomy, ForumState — обычные модели pydantic
  storage/        хранилище сообщений в DuckDB, таксономия и состояние форума в YAML
  services/       предобработка, поиск дубликатов, классификатор
  telegram/       сборка клиента, настройка форума, обработчик сообщений
  main.py         точка входа; task run вызывает её как python -m news_classifier.main
config/           categories.yaml (в репозитории), forum_state.yaml (пишет бот)
utils/            отдельный экспортер каналов, которым собирался датасет
notebooks/        обучение и анализ, см. ниже
data/             датасет, на котором обучалась модель
```

Датасет размеченных постов Telegram и ноутбуки, из которых получилась модель,
описаны отдельно: [`data/README_ru.md`](data/README_ru.md) и
[`utils/README.md`](utils/README.md).
